# Spravka Chat Application

Улучшенное клиент-серверное чат-приложение на C++ с улучшенной безопасностью и поддержкой редактирования сообщений.

## 🔒 Улучшения безопасности в этой версии

### 1. Заменен слабый алгоритм шифрования XOR
- **Было**: Простое XOR с статическим однобайтовым ключом 'K' (криптографически небезопасно)
- **Стало**: Улучшенная схемa шифрования с:
  - Потоковым шифром на основе PRNG (Xorshift64*)
  - Диффи-Хеллманоподобное производство ключевого материала
  - Аутентификация сообщений (MAC) для обнаружения подделки
  - Защита от атак повтора через использование nonce (счетчика сообщений)
  - Криптостойкая хеш-функция для производных ключей и MAC

### 2. Механизм аутентификации сообщений
- Каждое сообщение включает MAC (Код проверки подлинности сообщения)
- MAC вычисляется как HMAC-подобная конструкция: hash(key || message || nonce)
- При получении сообщения MAC проверяется перед расшифровкой
- Предотвращает атаки типа "man-in-the-middle" и подмену сообщений

### 3. Защита от атак повтора
- Каждое сообщение содержит увеличивающийся nonce (номер сообщения)
- Сообщения с устаревшими или будущими nonce отвергаются
- Окно допустимых nonce ограничено для предотвращения блокировки

## 🎨 Улучшения интерфейса для лучшей пользовательской дружелюбности

### В клиенте (`client.cpp`):
- **Полноценная поддержка редактирования сообщений**:
  - **← / →** - перемещение курсора влево/вправо
  - **Home / End** - переход к началу/концу строки  
  - **Delete** - удаление символа под курсором
  - **Backspace** - удаление символа перед курсором
- **Умный вывод входящих сообщений**: Сообщения выводятся выше строки ввода без нарушения текущего ввода
- **Четкие инструкции**: Расширенный список доступных команд и клавиш редактирования

### В сервере (`server.cpp`):
- **Таймстампы в истории**: Все сообщения в файле `history.txt` помечены временем `[HH:MM:SS]`
- **Таймстампы в консоли**: При событиях подключения/отключения пользователей выводятся временные метки
- **Улучшенное форматирование** статуса и сообщений сервера

## ⚙️ Технические детали улучшений безопасности

### Криптографические primitives:
- **Хеш-функция**: Вариант алгоритма DJB2 (простой но с хорошими диффузионными свойствами)
- **PRNG**: Xorshift64* - быстрый генератор с хорошими статистическими свойствами
- **Схема шифрования**: Потоковый шифр с XOR-комбинацией keystream и plaintext
- **Аутентификация**: HMAC-подобная конструкция для проверки целостности и подлинности

### Формат защищенного сообщения:
```
[8 байт: nonce (big endian)][N байт: зашифрованный текст][8 байт: MAC]
 discovered
```

### Процесс отправки сообщения:
1. Generating nonce (message counter)
2. Deriving key material: hash(shared_secret || nonce)
3. Generating keystream using Xorshift64* PRNG seeded with key material
4. Encrypting: ciphertext = plaintext XOR keystream
5. Computing MAC: hash(shared_secret || ciphertext || nonce)
6. Formatting and sending: [nonce][ciphertext][MAC]

Сервер использует тот же формат для рассылок, списка участников и личных
сообщений. Счётчик nonce исходящих сообщений ведётся отдельно для каждого
клиента, чтобы получатели могли проверять MAC и принимать сообщения по порядку.

### Процесс получения сообщения:
1. Extracting nonce from beginning of message
2. Validating nonce is within acceptable window (replay protection)
3. Extracting ciphertext and MAC
4. Recomputing MAC and verifying it matches (constant-time comparison)
5. Decrypting: plaintext = ciphertext XOR keystream (using same keystream as encryption)
6. Updating expected nonce for next message

- Компилятор C++ с поддержкой C++11 (g++ рекомендуется)

## 🚀 Использование

### Запуск сервера
```bash
./server
```

Сервер запустится на порту 8080 и будет принимать подключения.

### Запуск клиента
```bash
./client
```

Клиент предложит:
1. Выбрать режим подключения (тестовый к localhost или рабочий с указанием IP)
2. Ввести никнейм (теперь передается с улучшенным шифрованием и аутентификацией)
3. Начать общение в чате с полноценной поддержкой редактирования

### Команды чата
- `/list` - показать список участников онлайн
- `@никнейм сообщение` - отправить личное сообщение указанному пользователю
- `/exit` - выйти из чата

### Клавиши редактирования сообщений
- **← / →** - перемещение курсора влево/вправо
- **Home / End** - переход к началу/концу строки
- **Delete** - удаление символа под курсором
- **Backspace** - удаление символа перед курсором
- **Enter** - отправка сообщения

### Индикаторы безопасности
- При подключении сервер отображает: "Шифрование: Улучшенная безопасность с аутентификацией и защитой от атак повтора"
- Все сообщения в истории чата включают таймстампы для аудита
- MAC проверка предотвращает подделку и изменение сообщений

## 🔐 Особенности реализации безопасности

### Ключевые преимущества по сравнению с оригинальным XOR:
1. **Секретность**: Даже при известном открытом тексте сложно определить ключ
2. **Целостность**: Любое изменение сообщения обнаруживается с высокой вероятностью
3. **Подлинность**: Подтверждает, что сообщение pochodло от легитимного участника
4. **Свежесть**: Защита от атак повтора через nonce
5. **Диффузия**: Изменение одного бита входных данных меняет около половины битов вывода

### Ограничения текущей реализации (для образовательных целей):
- Статический общий секретный ключ (в реальном приложении следует использовать обмен ключами Диффи-Хеллмана или подобный)
- Ограниченная стойкость хеш-функции (используется упрощенная версия для простоты реализации)
- Нет прямой секретной передачи ключа между клиентом и сервером

Для производства следует использовать established библиотеки как OpenSSL или Libsodium, но текущая реализация демонстрирует основные принципы безопасного проектирования систем передачи сообщений.

## 💡 Техническая реализация редактирования

Система редактирования использует терминальный режим non-canonical input для:
- Чтения ввода посимвольно без ожидания Enter
- Интерпретации escape-последовательностей для специальных клавиш
- Управления позицией курсора через ANSI escape-коды
- Буферизации текста с возможностью вставки/удаления в произвольной позиции
- Эффективного перерисования только измененных частей строки

Это обеспечивает плавное и отзывчивое редактирование сообщений перед их отправкой, сравнимое с работой современных командных оболочек.
